# STQA Mini Project – Test Plan
**Problem Statement (SPPU):** Create a small application by selecting relevant system environment / platform and programming languages. Narrate concise Test Plan consisting features to be tested and bug taxonomy. Prepare Test Cases inclusive of Test Procedures for identified Test Scenarios. Perform selective Black-box and White-box testing covering Unit and Integration test by using suitable Testing tools. Prepare Test Reports based on Test Pass/Fail Criteria and judge the acceptance of application developed.

## 1. Test Plan Identifier
TP-LMS-01 – Library Management System (LMS) v1.0

## 2. Introduction
The LMS lets a librarian add books, register members, search, issue and return books, and calculates late fines. This plan defines the scope, approach, resources and schedule of testing.

## 3. Test Environment
| Item | Detail |
|---|---|

| OS | Windows 10/11, Ubuntu 22.04, macOS |

## 4. Features to be Tested
| ID | Feature | Rules |
|---|---|---|
| F1 | Add book | ISBN exactly 13 digits, title non-empty, copies ≥ 1, same ISBN adds copies |
| F2 | Register member | ID format `M` + 4 digits, name non-empty, age 5–100, no duplicates |
| F3 | Search | Case-insensitive search on title / author |
| F4 | Issue book | Member & book must exist, copy available, max 3 books, no duplicate issue, due date = +14 days |
| F5 | Return book | Must be issued to that member; stock increases |
| F6 | Fine calculation | Rs 5/day late, max Rs 500, negative days invalid |
| F7 | Login UI | Valid / invalid / empty / wrong-format credentials |

**Features not tested:** performance under load, database persistence, report printing.

## 5. Approach
- **White-box testing:** statement and branch coverage of `calculate_fine()` (4 independent paths: cyclomatic complexity V(G) = 3 decisions + 1 = 4) and of the `Book` validation code.
- **Black-box testing:**
  - **Equivalence Class Partitioning (ECP)** – member ID: {valid M1234}, {wrong prefix}, {non-digit}, {wrong length}.
  - **Boundary Value Analysis (BVA)** – ISBN length 12/13/14, age 4/5/6/99/100/101, fine cap 99/100/101 days, borrow limit 3/4.
- **Unit testing:** individual functions/classes (`calculate_fine`, `Book`, `Member`).
- **Integration testing:** `Library` with `Book` + `Member` (issue → return → fine flow), bottom-up approach.
- **UI/system testing:** Selenium automates the login page.

## 6. Pass / Fail Criteria
- A test case **passes** when the actual result equals the expected result.
- **Acceptance (exit) criteria:** ≥ 95% test cases pass, 0 errors, and no open Critical/Major defects.
- **Suspension criteria:** the build does not start, or more than 30% of test cases are blocked.

## 7. Bug Taxonomy (categories of bugs we look for)
| Category | Example bug in LMS | Severity |
|---|---|---|
| Requirement / specification bugs | Fine cap not defined, so unlimited fine | Major |
| Functional / logic bugs | Stock not decremented on issue; fine counted from issue date instead of due date | Critical |
| Boundary bugs | Age 100 rejected (`<` used instead of `<=`); 13-digit ISBN check off by one | Major |
| Input validation bugs | ISBN with letters accepted; empty title accepted | Major |
| Data / state bugs | Same book issued twice to one member; returning a non-issued book increases stock | Critical |
| Integration / interface bugs | `return_book` passes wrong date type to `calculate_fine` | Major |
| Calculation bugs | Rounding error or negative fine | Major |
| UI bugs | Error message not shown; wrong page title | Minor |
| Error-handling bugs | Program crashes on non-numeric age input (ValueError not caught) | Major |
| Performance bugs | Search becomes slow with many books (linear scan) | Minor |
| Security bugs | Password shown in plain text, no login lockout | Major |
